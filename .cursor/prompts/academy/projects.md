# Projects Prompt

Use this prompt when creating or improving project pages under `docs/projects/` or technology-specific project indexes.

## Purpose

Projects are portfolio proof. They must help learners demonstrate professional capability, not just complete a checklist.

## Required project qualities

Each project should include:

- A realistic business or platform scenario
- Clear functional and non-functional requirements
- A safe implementation plan
- Security, reliability, cost, and operational considerations
- Validation and testing guidance
- Recommended repository structure
- README expectations
- Future enhancements

## Student-to-professional progression

- Beginner projects should produce a working tool or automation with clear usage examples.
- Intermediate projects should combine multiple tutorials and include tests or validation scripts.
- Advanced projects should include production constraints, failure handling, observability, and security posture.
- Capstone projects should look like real platform work: architecture, trade-offs, rollout plan, operations guide, and incident response considerations.

## Anti-patterns

- Do not list moved or superseded projects as active portfolio builds.
- Do not create projects that are only reading or note-taking exercises.
- Do not include empty directories in suggested repository structures.
- Do not require paid cloud resources unless cost and cleanup are explicit.
- Do not use vague deliverables such as "understand the tool"; require working artefacts.
